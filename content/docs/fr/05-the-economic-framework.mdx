La tarification est l'endroit où la plupart des agences cachent leur économie. Le modèle MRVIN100 fait l'inverse : il publie le cadre, donc les chiffres sont la preuve du modèle.

## Ce qui est standardisé, ce qui ne l'est pas

Le modèle établit une distinction claire :

- **Le cadre est standardisé et universel.** Les pourcentages, les rôles, les garanties et les critères sont publiés une fois et s'appliquent partout. Exemples : la part de 40 % du développeur, la fourchette de 8 à 12 % du SDM, la norme de remplacement sous 72 heures.
- **Les prix absolus sont maintenus par zone de marché.** Ce qui est standard en Afrique centrale peut différer de l'Afrique de l'Ouest, de l'Afrique de l'Est ou de l'Europe. Chaque zone publie ses propres paramètres sous le même cadre.

C'est pourquoi il n'y a pas de liste de prix unique dans cette documentation. Le cadre est la constante ; les paramètres de zone sont les variables.

## La répartition publiée

Chaque contrat suit la même allocation :

| Allocation | Part |
| --- | --- |
| Développeur | 40 %, sacrée |
| Success Delivery Manager | 8 à 12 %, selon la complexité |
| Marketing | 12 %, organique d'abord |
| Agent d'acquisition | 3 à 7 %, base + commission + rétention |
| Fondateur | 3 %, proportionnel au chiffre d'affaires |
| Infrastructure technique | 5 % |
| Réserves | 5 % |
| Reste | réinvesti dans le réseau et les opérations |

La répartition est publiée ici, dans la documentation, et est la même pour chaque client dans chaque zone.

## Simulez votre cas

Comme le cadre est numérique, il peut être simulé. Le [simulateur](/fr/simulator) permet à un décideur de :

- Saisir une valeur mensuelle de contrat en FCFA ou en EUR
- Ajuster les parts variables (SDM et agent) dans leurs fourchettes publiées
- Voir la répartition se mettre à jour en temps réel sous forme de graphique
- Changer le point de vue de chaque acteur : entreprise, développeur, SDM, agent, État

Le simulateur applique exactement le cadre publié. C'est un outil de décision, pas un argumentaire de vente.

## Les paramètres de zone

Chaque zone de marché maintient son propre ensemble de paramètres, sous le même cadre. Les paramètres de zone typiques incluent :

- Les tarifs horaires de référence par niveau de séniorité (ex. Junior, Middle, Senior)
- Les conventions monétaires (zones FCFA, zones EUR, autres zones monétaires)
- Les ajustements de coût de vie locaux pour la base de la part du développeur
- Les variantes de SLA adaptées aux conditions locales, jamais sous le minimum du cadre
- Les modèles juridiques et contractuels alignés sur le droit local

Les paramètres de zone sont publiés et versionnés comme le cadre lui-même. Voir [zones de marché et standards](/fr/model/08-market-zones-and-standards) pour l'explication complète.

## Ce que le prix inclut

Quand un adoptant paie un contrat, il paie un système de livraison, pas un effectif :

- Le développeur (40 % de chaque contrat)
- Le Success Delivery Manager
- Les outils (Discord, GitHub, Cal.com, Formbricks)
- Les jalons qualité et le reporting
- La norme de remplacement sous 72 heures

## Le non honnête

Le modèle applique une marge minimale sur tous les projets sur mesure. Si un budget ne peut pas soutenir une rémunération équitable du développeur et un système de livraison sain, la réponse honnête est donnée plutôt que d'écraser le développeur. C'est ainsi que le modèle fonctionne pour tout le monde, ou pas du tout.
